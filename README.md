# Mini Booking

Тестовое задание: бронирование переговорной по часовым слотам. Backend на Laravel 13 и SQLite, frontend на Vue 3 и PrimeVue.

## Что нужно

PHP 8.3+ с `pdo_sqlite`, Composer, Node.js 20.19+.

## Запуск

Backend:

```bash
cd backend
composer setup
php artisan serve
```

`composer setup` ставит зависимости, создаёт `.env` и файл базы, запускает миграции и сидер. API будет на `http://localhost:8000`.

Frontend, в другом терминале:

```bash
cd frontend
npm install
npm run dev
```

Страница откроется на `http://localhost:5173`. Запросы к `/api` Vite проксирует на `http://127.0.0.1:8000`.

Отдельные команды, все из папки `backend`:

```bash
php artisan migrate    # миграции
php artisan db:seed    # расписание на 7 дней
php artisan test       # тесты
```

В `.env` важна одна настройка: `APP_TIMEZONE`, это часовой пояс расписания. По умолчанию `Europe/Moscow`.

Сидер можно запускать повторно. Существующие слоты и брони он не трогает, добавляет только недостающие.

## Уникальность брони

Отмена не удаляет бронь, а заполняет `cancelled_at`. На таблице `bookings` стоит частичный уникальный индекс по `slot_id` с условием `cancelled_at IS NULL`, поэтому активная бронь на слот может быть только одна.

При бронировании я не проверяю заранее, свободен ли слот. Сразу делаю insert и ловлю ошибку индекса, она превращается в 409. Два одновременных запроса на один слот оба пройти не могут.

Такой индекс есть в SQLite и PostgreSQL. В MySQL частичных индексов нет, там схему пришлось бы менять.

## Время

Приложение работает в поясе из `APP_TIMEZONE`. Сидер создаёт слоты в нём, а «сейчас» это время сервера. Слот считается прошедшим, если его начало меньше или равно текущему времени.

API отдаёт время с UTC-смещением и название пояса. Страница показывает даты в поясе расписания, а не в поясе браузера.

В базе время хранится без смещения, поэтому после смены `APP_TIMEZONE` базу надо пересоздать: `php artisan migrate:fresh --seed`.

## Заметки

- Тестов два, как в ТЗ. Остальные сценарии проверял руками в браузере.
- Список отдаёт слоты начиная с сегодняшнего дня одним ответом, без пагинации.
- Повторная отмена возвращает 204, неизвестный id брони даёт 404.
- Прошедший слот с бронью показывается как прошедший, отменить такую бронь со страницы нельзя.
